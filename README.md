# AIBOX

一个基于 Flutter 的三端内容聚合客户端，用来统一管理影视、小说和漫画来源，并在本地完成搜索、阅读、播放、下载、弹幕、规则编辑与插件扩展。配合公开的 [aibox-drpy-source](https://github.com/yunwuee/aibox-drpy-source) AI Skill，还可以让 AI 按真实站点证据创建、修复和验收自己的内容源。

AIBOX 运行在 Android、Windows 和 iOS 上。它不是一个固定内容站，也不会替用户提供某个特定站点的长期可用性；应用展示的内容、媒体地址和规则，取决于用户配置的来源、规则作者以及上游服务的状态。

> 本仓库是 AIBOX 的公开发布仓库，只存放构建产物和发布说明，不包含主应用源码。源码、插件 SDK 和内置引擎的开发工作在私有仓库中进行。

## 下载与安装

所有正式包都在 [Releases](https://github.com/yunwuee/AIBOX-public/releases) 发布，请从 [最新版下载页](https://github.com/yunwuee/AIBOX-public/releases/latest) 获取当前版本。每个版本的更新内容、构建时间和文件校验信息以对应 Release 页面为准。

| 平台 | 发布文件 | 选择建议 |
| --- | --- | --- |
| Android | `AIBOX-v<版本>-android-arm64-v8a.apk` | 绝大多数现代 64 位手机优先使用此包。 |
| Android | `AIBOX-v<版本>-android-armeabi-v7a.apk` | 仅用于仍为 32 位 ARM ABI 的旧设备。 |
| Android | `AIBOX-v<版本>-android-x86_64.apk` | 用于 Android 模拟器或 x86_64 设备，不适合普通 ARM 手机。 |
| Windows | `AIBOX-v<版本>-windows-setup.exe` | Windows 安装包，安装时可选择 AIBOX 数据位置。 |
| iOS | `AIBOX-v<版本>-ios-unsigned.ipa` | 未签名 IPA，需要用户自行签名或使用相应安装工具。 |

### Android

1. 在 Release 页面下载与设备 ABI 匹配的 APK。
2. 在系统设置中允许当前文件管理器安装应用（如系统提示）。
3. 安装后打开 AIBOX，在“设置”中检查数据目录、源和下载目录。

普通手机不要因为文件名更长就选择 `x86_64`；可在 Android 的设备信息工具中查看 ABI，也可以优先尝试 `arm64-v8a`。

### Windows

运行安装包完成安装。首次启动时可以选择应用数据位置，之后可在设置中查看并迁移数据目录。数据目录与安装目录分离，适合把运行时、插件、下载和缓存放到空间更充足的磁盘。

### iOS

公开 Release 提供的是未签名 IPA，不是可以直接从 App Store 安装的包。安装前需要准备自己的签名证书和描述文件；签名、侧载工具及 Apple 账户要求由用户自行确认。

## 影视、小说与漫画

AIBOX 将三类内容分成独立模块，每个模块可以使用自己的来源、分组和排序。主导航通常包含：

- **影视**：推荐、分类、源切换、搜索、详情、选集、线路和播放器。
- **小说**：书源切换、搜索、详情、目录、阅读器、书架和章节下载。
- **漫画**：漫画源切换、分类、详情、章节目录、漫画阅读器和图集下载。
- **仓库**：收藏、观看历史、阅读历史、继续浏览和已下载内容。

来源可以启用、停用、分组、排序和单独刷新。导入或编辑规则后，AIBOX 会刷新相应的索引；如果上游站点改版，规则可能暂时失效，可以在源管理器中重新编辑、替换或停用该来源。

## 用 AI 写源：影视、小说与漫画一网打尽

AIBOX 不只是播放器，也是 DS 源的运行、管理、调试和真机验收环境。公开项目 [yunwuee/aibox-drpy-source](https://github.com/yunwuee/aibox-drpy-source) 则把写源知识、规则语法、诊断流程和配套 CLI 封装成 AI Skill，让 Codex 或其他支持 `SKILL.md` 的 Agent 可以根据真实页面或接口证据生成和修复源。

两者配合后的工作流是：

```text
目标网站或 API
    -> AI 获取真实响应并判断站型
    -> 生成单文件 DS 源（var rule = { ... }）
    -> 完成 L1 / L2 / L3 验收
    -> 导入 AIBOX 并选择内容分组
    -> 在手机或电脑上播放、阅读和继续调试
```

> AIBOX 与 Skill 都不分发可直接使用的第三方站点源。用户需要提供自己有权访问和测试的目标；Skill 负责帮助分析和编写规则，AIBOX 负责在本地运行规则。

### 一套工作流覆盖四类内容

| 内容类型 | DS 类型 | AI 写源的最终目标 |
| --- | --- | --- |
| 影视 / 番剧 / 电影 / 电视剧 | `video` | 跑通首页、分类、搜索、详情、线路、分集和真实播放地址。 |
| 小说 | `novel` | 跑通书籍详情、章节目录和首末章正文，返回 AIBOX 可阅读的 `novel://` 结果。 |
| 漫画 | `comic` | 跑通漫画详情、章节和真实图片，并按需处理 `pics://`、防盗链、代理、WebP 或图片切片。 |
| 磁力 / BT | `bt` | 返回完整 magnet 或公开 torrent，由 AIBOX 本地 BT 引擎继续处理。 |

Skill 能按证据选择模板继承、HTML、HTML/API 混合、App API、JSON 或 SPA 等实现路线，也可以处理动态域名、Cookie、请求头、POST、签名、解密、简单验证码/OCR、图片代理和海阔规则迁移等场景。它不是“输入一个域名就盲猜选择器”的代码生成器；遇到登录墙、Cloudflare、滑块、DRM、缺失凭据或强风控时，会保留失败证据并停止猜测。

### 安装写源 Skill

1. 从 [aibox-drpy-source 最新 Release](https://github.com/yunwuee/aibox-drpy-source/releases/latest) 下载 `aibox-drpy-source-skill.zip`。
2. 解压后，把其中的 `aibox-drpy-source` 目录放入 Codex Skills 目录。
3. 在 Skill 目录执行 `npm ci` 安装依赖，然后重启 Codex 或重新加载 Skills。
4. 运行 CLI 的 `help` 和 `doctor` 检查安装状态。

Windows 下的安装与检查示例：

```powershell
Copy-Item .\aibox-drpy-source "$env:USERPROFILE\.codex\skills\aibox-drpy-source" -Recurse -Force
npm ci --prefix "$env:USERPROFILE\.codex\skills\aibox-drpy-source"
node "$env:USERPROFILE\.codex\skills\aibox-drpy-source\scripts\aibox-skill-cli.mjs" help
node "$env:USERPROFILE\.codex\skills\aibox-drpy-source\scripts\aibox-skill-cli.mjs" doctor
```

macOS、Linux、从 Git 安装、更新和卸载方法见 [完整安装说明](https://github.com/yunwuee/aibox-drpy-source#安装)。

### 直接让 AI 写一个源

安装后，在对话中明确提到 `$aibox-drpy-source`。例如：

```text
使用 $aibox-drpy-source，为 https://example.com 编写一个影视/番剧 DS 源。
先获取真实页面和接口证据，再判断站型并生成规则。
使用真实 ID 跑通首页、分类、详情、搜索和播放，完成 L1/L2/L3 验收。
把最终源码保存到当前工作区 output/source.js，不要上传或分享。
```

将内容类型替换为 `novel` 或 `comic`，同一套流程就会改为验证小说目录与正文，或漫画章节与图片。修复已有源时，提供源文件路径、AIBOX 日志和具体失败阶段，AI 会优先保留仍然有效的逻辑，只修复实际断点。

### 为什么要做 L1、L2、L3 验收

| 级别 | 检查内容 | 能证明什么 |
| --- | --- | --- |
| L1 | JavaScript 语法、AST、模板、字段和协议契约 | 文件结构正确，具备进入运行测试的基础。 |
| L2 | 首页、分类、详情、搜索、播放或正文等真实单接口 | 目标站点当前确实返回有效数据。 |
| L3 | 使用真实分类 ID、作品 ID、章节 ID 或播放 ID 串联完整链路 | 上下游数据可以真正衔接，而不是每个接口孤立通过。 |

只有 L1 通过并不等于源可用。影视应验证真实播放结果，小说应验证首末章正文，漫画应验证首末章首尾图片和文件头；最终仍建议把生成的 `.js` 文件导入 AIBOX，在实际设备和网络环境中验收。

Skill CLI 还提供 `triage`、`compose`、`lint`、`check`、`heal`、`save`、`share`、`hiker-import`、`debug-selector` 等命令。`heal --apply` 会修改文件，`share` 会上传源码，因此 Agent 只应在用户明确允许时执行。完整命令、提示词和能力边界请查看 [aibox-drpy-source 自述文件](https://github.com/yunwuee/aibox-drpy-source#readme)。

## 播放器

AIBOX 使用本地集成的 Predidit/Kazumi 同源 `media_kit` 播放体系，并保留 AIBOX 自己的缓冲、弹幕、字幕、下载和会话生命周期处理。

### 播放能力

- HLS / m3u8、MP4 和常见直链视频。
- 带 `Referer`、`User-Agent`、Cookie 等请求头的媒体（由来源规则提供时）。
- 本地下载视频和可访问的本地媒体文件。
- 多播放线路、多分集、切集和下一集。
- 倍速、全屏、画中画（系统和设备支持时）、记忆播放进度。
- 音轨、字幕轨、弹幕、显示区域、透明度和过滤设置。
- Anime4K/超分着色器（设备性能、视频格式和渲染路径满足条件时）。
- 弱网缓冲、回拖缓存和兼容的点播 HLS 智能预取。

### 解码器与渲染器

播放器设置允许按平台选择硬件解码器；Android 还可以选择视频渲染器。可选项包括：

| 平台 | 硬件解码器/渲染器 |
| --- | --- |
| Android | `auto-safe`、`auto`、`auto-copy`、`mediacodec`、`mediacodec-copy`、`vulkan`、`vulkan-copy`；渲染器包括 `gpu`、`gpu-next`、`mediacodec_embed`。 |
| Windows | `auto-safe`、`d3d11va`、`d3d11va-copy`、`nvdec`、`nvdec-copy`、`vulkan`、`vulkan-copy`、`dxva2`、`dxva2-copy`。 |
| iOS | `auto-safe`、`videotoolbox`、`videotoolbox-copy`。 |

实际可用选项由设备 GPU、系统版本、视频编码、驱动和当前 media-kit 构建决定。AIBOX 会在当前播放会话内尝试安全配置；出现“有声音无画面”、解码器初始化失败或视频输出不可用时，会按兼容模式回退到软件解码。回退不会永久改写用户的偏好，也不会把设备解码问题误判成源站失效。

普通暂停、拖动、进入或退出全屏不会重建播放器。只有切集、切源、退出播放器或当前媒体确实失败时，才会清理对应播放会话。

## 弹幕系统

AIBOX 支持内置 DanDanPlay 来源，也支持多个用户自己部署或配置的 `danmu_api` 兼容服务。

- 来源可以添加、编辑、测试、启用、停用、排序和删除。
- 启用来源会并发搜索，结果按来源分组逐步出现。
- 每个来源分别显示加载中、成功、空结果、超时、限流、权限错误、协议错误和不可用状态。
- 一个来源失败不会熔断其他来源；可以只重试失败来源。
- 选择某个来源的作品和分集后，只加载该来源的弹幕，不自动合并多个来源，避免重复和时间轴冲突。
- 匹配结果会保存为带来源身份的缓存；服务端远端 ID 失效时会有限地重新搜索和绑定。
- 播放器内保留弹幕开关和长按修改匹配，设置页负责总开关及来源管理。

如果没有 DanDanPlay 官方密钥，其他已启用的自定义来源仍可独立搜索和加载。自定义地址、Token 和请求头只保存在用户设备中，README 和日志不会展示这些敏感信息。

## 字幕与本地 OCR

AIBOX 正在集成本地字幕处理能力，当前功能以版本和平台实际集成状态为准：

- 对视频已有的内嵌字幕、外部字幕 URL、外部字幕文本和来源传入字幕进行处理。
- 支持原文、双语和仅译文显示模式；双语默认原文在上、译文在下。
- 已有字幕轨可以进行繁体中文到简体中文转换；英语、日语、韩语等神经翻译模型需要在设置中单独管理，模型是否可下载以当前版本页面为准。
- 本地 OCR 支持自动底部字幕区域，也支持手动框选字幕区域。
- 对连续视频帧进行稳定去重，避免同一句字幕重复刷新。
- 字幕浮层位于视频和弹幕之上、播放手势层之下；长按可以解锁并移动字幕位置，位置不会被系统状态栏遮挡。
- 没有字幕轨时不会伪装成“正在生成字幕”；OCR 也需要当前平台已集成相应能力。

OCR 和翻译不会阻塞视频首帧。模型缺失、平台未集成、内存不足或单帧处理失败时，会保留原字幕或关闭本次转换，不停止播放。

## 内置浏览器与视频嗅探

AIBOX 提供基于 `flutter_inappwebview` 的内置浏览器，适合访问来源网站、查看页面或处理需要网页上下文的媒体。

1. 从工具箱，或源操作菜单中的“网站首页”进入内置浏览器。
2. 等待页面加载，必要时手动点击网页中的播放按钮。
3. 当页面发起媒体请求后，工具栏的视频角标会显示已嗅探到的资源数量。
4. 点击角标，选择需要的媒体链接。
5. 点击“播放”会跳转到 AIBOX 播放器；点击“下载”会使用当前页面标题创建下载任务。

浏览器会监听页面中的媒体资源、XHR/fetch 和常见播放请求，但不保证所有 DRM、加密、强校验、WebRTC 或只在浏览器内部解码的内容都能嗅探。遇到空列表时，可以刷新页面或重新触发播放。

## 下载与离线内容

下载管理支持多种任务类型：

- 普通 HTTP 文件和 Range 分段下载。
- HLS/m3u8 分片下载、断点续传和任务恢复。
- 影视视频、小说章节、漫画章节/图集。
- 下载任务暂停、恢复、重试、取消、删除和详情查看。
- 下载完成后从本地播放或阅读。
- BT/磁力下载入口及本地 BT 引擎（设备和构建支持时）。
- 已完成内容的分享；部分 HLS 可合并为单个可播放文件，受加密方式限制。

并发数越高不一定越快，最终速度还取决于源站限速、网络、磁盘、设备温度和任务类型。DRM、特殊加密 HLS 或受保护资源可能无法下载或导出。

用户下载的视频、漫画和小说属于用户数据，不会被普通“清理缓存”操作删除。清理缓存主要处理图片缓存、视频缓冲、翻译结果和临时文件；删除下载内容需要在下载管理中明确操作。

## drpy 源管理

AIBOX 内置本地 drpy-node 引擎，用来运行用户导入的内容规则。源规则不是 AIBOX 固定绑定的站点列表，用户可以按需要维护自己的来源；需要从目标网站创建或修复 DS 源时，可以使用上面的 [aibox-drpy-source AI 写源流程](#用-ai-写源影视小说与漫画一网打尽)。

### 支持的源类型

当前源管理器识别以下引擎类型：

| 类型 | 常见用途 |
| --- | --- |
| `JS` | drpy JavaScript 规则，AIBOX 当前最常用的源格式。 |
| `PY` | Python 规则（是否可运行取决于当前引擎和平台）。 |
| `PHP` | PHP 规则（是否可运行取决于当前引擎和平台）。 |
| `CAT` | CAT/AV视频类兼容规则。 |
| `XBPQ` | XBPQ 配置型规则。 |

实际可用能力由规则内容和当前内置引擎决定；导入一个文件并不代表它一定适配所有平台。

### 导入和维护

在“源管理器”中可以：

- 导入本地 JS 文件或其他支持格式。
- 从云剪切板、分享文本或规则内容导入。
- 自动识别源名称、引擎类型和影视/小说/漫画分组。
- 信息不足时手动选择分组和内容类型，不把不确定的规则静默放错位置。
- 启用、停用、排序、分组、重命名和删除来源。
- 编辑规则源码，查看规则预览并运行选择器测试。
- 使用在线写源 IDE 创建或修改 drpy 规则，也可以导入 AI Skill 生成并已完成验收的单文件 DS 源。
- 分享规则文件，或从源操作菜单进入网站首页、编辑、重新下载和删除。
- 处理 JS 规则依赖的 `_lib*.js` 等辅助文件（以当前规则包声明为准）。

最小的 drpy JS 结构通常类似下面的形式，具体字段以 drpy 规则规范和目标站点页面为准：

```javascript
var rule = {
  title: '示例来源',
  host: 'https://example.invalid',
  url: '/search/**',
  searchUrl: '/search/**',
  searchable: 1,
  quickSearch: 0,
  filterable: 0,
  class_name: '分类1&分类2',
  class_url: '1&2',
  detailUrl: '/detail/fyid',
  play_parse: true,
};
```

上面的地址仅用于展示字段结构，不是可直接使用的站点配置。请只导入你有权访问和使用的来源，并遵守目标站点的服务条款。

### 规则排错建议

1. 先在源管理器中确认规则所属分组和引擎类型。
2. 用“规则预览/测试”检查搜索、详情、选集和播放解析分别是哪一步失败。
3. 检查站点是否改版、是否需要登录态、是否需要请求头或是否限制访问频率。
4. 只启用稳定来源；暂时不可用的来源可以停用，不影响其他来源。
5. 不要把 Cookie、Token、账号密码或管理后台密钥写进公开分享内容。

## 插件系统

AIBOX 提供 `native-js` 插件运行时，让插件通过清晰的 manifest 和声明式 UI 接入宿主，而不是把任意原生动态库直接塞进应用安装包。

### 插件可以做什么

插件可以根据授权范围贡献：

- 首页卡片、整页入口、导航栏入口和工具箱入口。
- 源管理器入口、插件内 route 页面和多 surface 页面。
- 搜索、媒体选择、网页嗅探、下载任务和内容详情等工作流。
- 插件自己的图标、分类、作者、主页、版本和更新信息。
- 插件私有 KV 存储，以及受权限和域名白名单限制的网络请求。

宿主会隔离插件目录和私有存储，校验插件 ID、入口路径、manifest 版本和权限声明。未满足必需权限、路径不安全或版本不兼容的插件不会直接启用。

### 当前插件契约

当前推荐使用：

```text
contractVersion: 3
manifestVersion: 2
apiVersion: 2
runtime: native-js
uiSchemaVersion: 1
pluginHostVersion: 0.2.0
```

插件 UI 使用声明式文档，常用组件包括 `screen`、`scroll`、`section`、`row`、`column`、`text`、`icon`、`image`、`badge`、`card`、`contentCollection`、`contentCard`、`listTile`、`button`、`iconButton`、`chipGroup`、`segmented`、`textField`、`switch`、`progress`、`loadingState`、`emptyState` 和 `errorState`。

### 最小 manifest 示例

```json
{
  "manifestVersion": 2,
  "apiVersion": 2,
  "runtime": "native-js",
  "id": "example.tool",
  "name": "示例工具",
  "version": "1.0.0",
  "type": "page",
  "entry": "main.js",
  "placements": ["toolbox"],
  "permissions": {
    "required": ["network", "storage"],
    "optional": ["download"]
  },
  "allowedHosts": ["example.com"],
  "surfaces": [
    {
      "id": "main",
      "kind": "page",
      "title": "示例工具",
      "placements": ["toolbox"]
    }
  ]
}
```

这是用于说明字段关系的最小示例，不保证每个版本都可以不加修改直接安装。插件编辑器和模板会生成与当前宿主契约匹配的基础结构；开发插件时应以对应版本的 SDK contract、manifest schema 和权限列表为准。

### 权限与安全

常见权限按能力拆分，包括网络访问、搜索、页面跳转、下载、私有存储、历史、收藏、下载任务控制、源读取、媒体选择、文件选择、viewer 媒体嗅探和 BT viewer 等。高风险能力应放入 `optional`，只在用户明确启用后使用；网络插件应配合 `allowedHosts` 限制域名范围。

插件不能绕过宿主权限直接访问任意文件、请求任意域名或加载未经宿主审核的原生动态库。插件分享给他人前，应移除账号、Cookie、Token、私有接口和个人文件路径。

## 数据、缓存与备份

AIBOX 将应用设置、源配置、历史、收藏、下载任务、插件配置、阅读进度和文件型数据分开管理。Windows 支持把应用数据迁移到其他磁盘；运行时、插件、下载和缓存目录也会随数据位置变化。

- **书架和下载**：属于用户数据，普通缓存清理不会删除。
- **图片和视频缓冲**：属于可再生成缓存，可以在设置中清理。
- **规则和插件**：属于用户配置，建议在修改前导出或备份。
- **WebDAV 备份**：可以备份设置、源配置、收藏、历史等结构化数据；是否包含大体积下载文件，以备份页面的实际状态为准。
- **恢复数据**：恢复后不会自动替用户下载缺失的模型、规则依赖或视频文件。

清理缓存前，应用会区分可清理缓存和用户内容；如果正在播放、阅读或使用某个模型，AIBOX 会先结束对应任务，再清理不再使用的文件。

## 快速上手

### 第一次打开

1. 安装并启动 AIBOX。
2. 在“设置”中确认数据目录、下载目录和缓存占用。
3. 进入“源管理器”，导入你自己的规则文件或分享内容。
4. 导入时选择“影视”“小说”或“漫画”分组；无法识别时按规则用途手动指定。
5. 返回对应首页，选择来源并执行搜索。

### 播放一部影视

1. 在影视首页选择来源和分组。
2. 搜索作品并打开详情。
3. 选择线路、分集或解析结果，等待播放器加载。
4. 在播放器中调节倍速、字幕、弹幕、解码器和画面设置。
5. 播放进度会按作品和分集保存，之后可以从“仓库”继续观看。

### 阅读小说或漫画

1. 在小说/漫画首页选择对应来源。
2. 搜索并打开作品详情。
3. 点击章节进入阅读器，调整字体、主题、翻页或图片显示方式。
4. 使用书架收藏作品；需要离线使用时，在详情页或批量下载面板加入下载任务。

### 使用浏览器嗅探视频

1. 打开工具箱或源菜单中的“网站首页”。
2. 在内置浏览器中访问页面并触发播放。
3. 点击视频数量角标，选择“播放”或“下载”。
4. 播放会进入 AIBOX 播放器，下载会使用页面标题创建任务。

## 常见问题

### 为什么搜索不到内容？

先确认来源已启用，再在源管理器测试搜索接口。搜索结果受规则、网络、站点改版、登录态和访问频率影响；换一个来源或稍后重试通常比反复刷新同一来源更有效。

### 为什么某个来源失败会显示错误？

AIBOX 会把每个来源的加载、空结果、超时、限流和协议错误分开显示。单个来源失败不会取消其他来源；可以只重试失败来源。

### 为什么播放器有声音但没有画面？

打开播放设置，先使用平台默认的 `auto-safe` 和自动渲染器。若仍无画面，可以临时关闭硬件解码或切换 Android 的 `gpu`/`gpu-next`。不同设备和视频编码对硬解支持差异很大，应用会在当前会话内自动回退。

### 为什么视频嗅探不到？

页面可能使用 DRM、WebRTC、加密请求、动态签名或浏览器内部 MediaSource。可以先刷新页面、重新触发播放；如果资源始终不出现在嗅探列表，AIBOX 不会强行把不可访问的内容当作普通直链。

### 清理缓存会不会删除下载或书架？

正常的缓存清理不会删除书架、收藏、阅读进度和已完成下载。删除下载文件需要在下载管理中明确确认；在清理前仍建议阅读确认框中的具体范围。

### iOS 为什么不能直接安装？

公开包是未签名 IPA。iOS 要求应用使用有效签名和描述文件安装，用户需要自行准备签名环境或使用可信的侧载方式。

### 插件为什么没有显示？

检查插件的 `manifestVersion`、`apiVersion`、`runtime`、入口文件、surface 和必需权限是否符合当前宿主版本。插件还可能因为 ID 不安全、路径越界、域名不在白名单或权限未批准而被禁用。
